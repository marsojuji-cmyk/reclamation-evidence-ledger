## Hyper-scaler triage (adopted doctrine)

- **Scale vector:** engineering quality of the repo — not pipeline throughput.
- **COMPOUNDS:** correctness verification, test coverage, pip-installability,
  CI enforcement, documentation accuracy.
- **DEGRADES with volume:** more sites/seasons (multiplies invalid packets
  while geocoding is unverified; multiplies repo weight via committed build
  output), more features on a stopped pipeline, more documentation.
- **Stop condition:** CI green + P0/P1 findings fixed or explicitly parked;
  nothing committed that restarts screening.

## Findings

### P0 — correctness & honesty (fixed)

- **F1. `dls_to_latlon` published-broken; docs claimed ±300 m.** The
  docstrings in `ledger/sites.py`, the `geo_method` registry field (which
  flows into every packet), the packet caveats in `ledger/change.py`, the
  rendered HTML in `ledger/render.py`, and three README spots all stated
  ~±300 m — known-false since 2026-10-09. All corrected to reference the
  published withdrawal. Published packets on disk were NOT rewritten
  (history stays history; the negative result covers them).
- **F2. No ground-truth test existed for the most important function.**
  Added `tests/test_geocode.py`: grid-geometry pins (LSD spacing 402 m,
  township/range 6-mile steps, boustrophedon parity — all passing, so any
  future fix must preserve the geometry) plus an xfail work-order test that
  stays visibly failing until the function verifies against independent
  ground truth. Survey math is not fixed by intuition — that is how the bug
  got here. (Side note found while testing: same-column sections differ
  ~75 m in longitude per township row because range offsets are statute
  miles at the site's latitude — a real but minor approximation, two orders
  below the published defect. Pinned in the test, not asserted exact.)
- **F3. README said "11 of 11 tests" — there are 17 (now 23 with the new
  module).** Fixed. The demo must be perfect: the README is the product
  page, and a wrong test count is a wrong product page.
- **F4. README "Evidence" section read as a positive claim.** The 99
  packets / 71 detected / 28 identified now carry their 2026-10-09 status
  inline: retained as the published record, not as evidence of recovery.

### P1 — integration: the whole widget (fixed)

- **F5. The package wasn't installable.** `sys.path.insert(0, ...)` hacks in
  all 3 test files and `ops/assess_all.py`. Added `pyproject.toml`
  (`reclamation-ledger`, console entry points for all 7 CLIs); removed every
  hack. `pip install -e .` verified; entry points verified from outside the
  repo.
- **F6. `ops/assess_all.py` hardcoded `.venv/bin/python`** — broken on any
  machine without that exact venv, including fresh clones. Now
  `sys.executable` (matching `ledger/pipeline.py`, which already did it
  right).
- **F7. `packet_name()` hardcoded `"2025-2026_growing_seasons"`** — a
  time-bomb for the next period. Now a `--period` CLI flag; reuses
  `ledger.packet.packet_filename` instead of a wrapper.
- **F8. `sha256_file` duplicated** in `ledger/packet.py` and
  `ledger/imagery.py`. One home now (`ledger.packet`).
- **F9. No lint, no format enforcement** — clean by discipline, which
  doesn't scale. CI now runs `ruff check` + `ruff format --check`; fixed 30
  auto-fixable findings, hand-fixed 13 (unused imports, `zip(strict=True)`
  on 8 same-length-by-construction zips — silent truncation is now a loud
  error, matching this codebase's philosophy — ambiguous `l` variables,
  `datetime.UTC`, import sorting). 19 files reformatted.
- **F10. `test_observation_count_definitions` hardcoded {2023,2024} /
  {2025,2026}** — rots on the next period. Now reads each packet's own
  `baseline_assessment` transform.
- **F11. CI syntax-check compiled `packets/`** (103 JSONs — a no-op).
  Scoped to `ledger schemas ops tests`.

### P2 — parked with reasons (not fixed)

- **Geocoding formula fix.** Requires independent ground-truth coordinates
  (20,000-well scale or a verified reference table). Guessing is how the
  bug got here. The xfail test is the work order.
- **`docs/` weight (25 MB repo).** 103 per-site HTML files are build output
  committed to git; every season multiplies them. But `docs/index.html` is
  the DEPLOYED dashboard — removing pages breaks the live site. Parked:
  future renders should deploy from CI artifacts or a deploy branch, not
  from committed build output.
- **Three site outputs** (`site/` marketing pages, `docs/index.html`
  dashboard, `ledger/render.py` → `out/ledger/`). Which is the product is a
  product decision, not an engineering one. Parked for the operator.
- **CI speed.** The test job installs the full heavy stack (rasterio,
  geopandas, …) for unit tests. Splitting unit vs integration deps would
  halve CI time — real, but cosmetic while the pipeline is stopped.
- **`pilots/pilot-02.txt` header** still carries the old ±300 m line. It's
  a committed historical artifact of the selection run; the generator
  (`ops/select_pilot02.py`) is fixed. History stays.
